# 테스트와 재현 규칙

## 작업 순서

1. 증상을 재현하고 숫자나 렌더 결과를 먼저 확인한다.
2. 수정할 함수의 모든 호출부를 찾아 공통 원인을 한 곳에서 고친다.
3. 기존 테스트가 덮는지 먼저 확인하고, 비어 있을 때만 가장 작은 회귀 테스트를 추가한다.
4. 수정 전 상태로 잠깐 되돌렸을 때 새 테스트가 같은 증상으로 실패하는지 확인한다.
5. 관련 테스트 후 전체 검증을 실행한다.

## 테스트 작성 시 주의

- 화면 결함 소크에는 `Draw`를 포함한다.
- 렌더 테스트 카메라는 정수가 아닌 위치도 포함한다.
- 소크의 프레임 간격은 고정 `1/60`만 쓰지 말고 간헐적 0.1초 스톨을 섞는다.
- 던전 생성은 희귀 결함을 잡도록 40~200개 시드를 사용한다.
- 임시 계측 테스트는 `zz` 접두로 만들고 완료 후 삭제하거나 정식 테스트로 승격한다.
- pty 스크린샷은 한글 폭 에뮬레이션이 부정확하므로 플레이필드 확인에만 사용한다.

## 기존 보호 범위

- `render_test.go`, `draw_test.go`: 넓은 문자 동기화, 좌표 역변환, 벽 위 렌더링.
- `overlay_test.go`, `minimap_test.go`: 최소 화면 도움말·설정과 미니맵 가시성.
- `walls_test.go`, `doorway_test.go`, `soak_test.go`: 대시·소환·문·좁은 통로 충돌.
- `ammo_test.go`, `balance_test.go`: 탄약 전환과 체력 경제.
- `move_test.go`, `evdev_linux_test.go`: 키 상태와 Linux 입력 디코딩.
- `zoom_test.go`, `camera_test.go`: 배율 불변성과 카메라 박자.
- `telegraph_test.go`, `elite_test.go`: 공격 예고와 정예 규칙.
- `rooms_test.go`, `props_test.go`, `fov_test.go`: 특수방, 지형, 캐시 무효화.
- `bench_test.go`: 프레임 비용과 할당 예산.

전체 검증은 `AGENTS.md`의 명령을 그대로 사용한다.
